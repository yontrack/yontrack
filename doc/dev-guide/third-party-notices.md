# Third-party notices

Yontrack is sold under a commercial license and installed by its customers, as two images. Most open
source licenses of the libraries they ship are conditions on redistribution: the license text, the
copyright notices and, for Apache-2.0, the `NOTICE` file of each library go with the copies we give
out. Each image therefore ships a `THIRD-PARTY-NOTICES.txt` under `/app/` (#2182).

## What is in it

The same libraries as the SBOM of the image (see [the SBOM stamp](ci-evidence.md)), each with:

- its name, version, the licenses the SBOM declares and its package URL;
- verbatim, every license, notice or copying file it packages: for a jar, `LICENSE*`, `NOTICE*`,
  `COPYING*` at its root or anywhere under `META-INF/`; for an npm package, the same names at its
  root. A file identical to one already given refers to it instead of repeating it.

Then an appendix with the standard text of every license declared by a library which packages no such
file of its own - about 100 backend jars and a dozen UI packages.

## Where it comes from

| Image   | Generated by                                                                 | License texts                       |
|---------|------------------------------------------------------------------------------|-------------------------------------|
| backend | `./gradlew :ontrack-ui:thirdPartyNotices` (`ThirdPartyNoticesTask` in `buildSrc`), from the jars of the external modules of the runtime classpath and the CycloneDX SBOM of `cyclonedxDirectBom`; Jib adds it to the image | `ontrack-ui/src/notices/licenses/`  |
| UI      | the `notices` stage of `ontrack-web-core/Dockerfile`, running `notices/third-party-notices.js` on `npm sbom --omit dev --omit optional` and `node_modules` | `ontrack-web-core/notices/licenses/` |

The two generators write the same format: change both together. Each is unit tested
(`ThirdPartyNoticesTest`, `__tests__/notices/thirdPartyNotices.test.js`).

## When the build fails

- **No text for a license**: a new library packages no license file and declares a license with no
  text in the directory above. Add the SPDX text as `<SPDX id>.txt` - from
  `https://github.com/spdx/license-list-data/tree/main/text` - or, for a license the SBOM gives by
  name, as `<name>.txt`.
- **A library packages no license file and declares no license**: find its license upstream before
  shipping it; there is nothing the notices can say for it.
- **On the classpath but not in the SBOM** / **in the SBOM but not installed**: the two inventories
  disagree, which is a bug of the build, not of the library.

## Out of scope

The OS packages and the JRE of the base images (Alpine, Zulu), which carry their own license files,
and any license policy: the notices list, they do not judge.
