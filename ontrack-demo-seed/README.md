# ontrack-demo-seed

Resets and seeds the demo environment through the Yontrack API. For how it works, how to run
it, and how to add to it, see [`doc/dev-guide/demo-seed.md`](../doc/dev-guide/demo-seed.md).

This file is the other half: a map of what the seeded demo contains and where to find it, for
a human looking for a feature to screenshot or walk through. It is generated by reading
[`DemoContent`](src/main/java/net/nemerosa/ontrack/demo/seed/DemoContent.kt), not by running
the seed — keep it in sync by hand whenever that file changes.

## What to see where

| Feature                                    | Where                                                              | What you'll see                                                                          |
|---------------------------------------------|----------------------------------------------------------------------|--------------------------------------------------------------------------------------------|
| Full promotion ladder                       | `petclinic` / `main`, builds `101`, `104`, `107`                     | `BRONZE` → `SILVER` → `GOLD`, promoted in order                                            |
| Validation warning                          | `petclinic` / `main`, build `102`                                    | `SECURITY.SCAN` passes with a `WARNING`                                                    |
| Validation failure blocking promotion       | `petclinic` / `main`, builds `103` and `106`                         | `INTEGRATION.TESTS` / `UNIT.TESTS` fails; the build carries no promotions                  |
| Workflow-backed promotion, passing          | `petclinic` / `main`, build `107`, `CANARY` promotion run             | 1-start / 2-parallel / 1-join workflow, every node `SUCCESS`                               |
| Workflow-backed promotion, failing          | `petclinic` / `release-1.3`, build `89`, `CANARY` promotion run       | Same DAG; `performance-gate` reports `ERROR`, `promote-canary` is `CANCELLED`              |
| Maintenance branch alongside `main`         | `petclinic` / `release-1.3`                                          | Its own promotion ladder and its own (failing) `CANARY` workflow                           |
| Build dependency graph                      | `petclinic-ui` / `main`, builds `58` and `59`                        | Links down to `petclinic` builds, which link down to `common-library` builds               |
| Environments and deployments                | `staging` and `production` environments                              | `petclinic` `105` deployed on staging, `104` deployed on production                        |
| Shared dashboard                            | Dashboard picker → "Yontrack demo"                                    | `BranchStatuses`, `EnvironmentList`, `LastActiveProjects` and `PromotionFrequencyChart` widgets |
| Self-hosted changelog                       | `yontrack` / `main`                                                   | One build per commit since the last release, always current, `BRONZE` only                 |

## Projects

| Project           | Branches                    | Role                                                                |
|--------------------|------------------------------|----------------------------------------------------------------------|
| `common-library`   | `main`                       | Bottom of the dependency graph; `petclinic` links to its builds       |
| `petclinic`        | `main`, `release-1.3`        | The main demo project — full pipeline, both promotion ladders         |
| `petclinic-ui`     | `main`                       | Consumes `petclinic`, so the demo has a dependency graph to walk       |
| `yontrack`         | `main`                       | Yontrack's own changelog, reseeded from git on every run              |
